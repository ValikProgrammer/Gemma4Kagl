## Ожидает решения

### thinking_budget выше 4096
- Идея: 11800 (тяжелым шагам не хватает 4096).
- Проблема: рассуждение и ответ лежат под `max_output_tokens`. Запрос + `max_output_tokens` <= 32768.
  При 11800 нужен `max_output_tokens` ~16000. Запрос тогда может быть только ~16700 токенов.
  Пики запроса 15-16.4k, шаг добавляет до 4k. Снова будет `ContextWindowExceededError`.
- Вариант: `thinking_budget` ~8000, `max_output_tokens` 12288, `include_thoughts: false`
  (рассуждение не копится в истории).
- Статус: не внесено.

## 2026-10-27

### max_output_tokens 16384 -> 12288 (коммит eef9800)
- Файл: `sample_submission/configs/sampling.yaml`.
- Почему: в прогоне 12B (v2) две задачи из трех остановила ошибка
  `This model's maximum context length is 32768 tokens ... prompt contains at least 16385 input tokens`.
  16385 + 16384 = 32769 > 32768. Харнес не повторяет такую ошибку.
  Пострадали fastapi_15661 (шаг 34) и requests_7505 (шаг 14).
- Что измерили (трассы v2): запрос растет на 1-3k за шаг и падает с ~16k до ~5-7k после сжатия истории.
  Пики: 15139, 15685, 15724, 16143. Один шаг добавлял до 4k.
  Обычный ответ 30-1700 токенов. Два тяжелых шага fastapi 4269 и 4128 (упираются в бюджет 4096).
  Один шаг rich взял все 16384 токена (обрыв).
- Риск: при 12288 допустимый запрос 20480. Худший случай ~20.4k. Запаса почти нет.

### Модель 12B -> 31B, max_time_minutes 20 -> 8 (коммит e98ff9b)
- Файлы: `sample_submission/agent.yaml`, `sub_agents/code_analyzer.yaml`, `eval_config.yaml`.
- Почему: 12B дала 0 из 3 и 10-30 секунд на шаг. 8 минут на задачу: около 120 задач,
  официальный лимит времени неизвестен.
- Статус: версия 3 ноутбука (31B) запущена, результата пока нет.
